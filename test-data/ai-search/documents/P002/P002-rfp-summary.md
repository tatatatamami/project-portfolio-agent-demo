# P002 RFP Summary - Player Support AI Agent

## 1. 背景

Customer Aのプレイヤーサポート部門では、月間問い合わせ件数が前年比40%増加し、サポートチームの対応能力が限界に達していた。特にゲームアップデート直後の24〜48時間に問い合わせが集中し、初回応答に最大10分かかる状況が常態化していた。一方、問い合わせ内容の約60%は既存FAQやゲームガイドで対応可能なものであり、AIエージェントによるセルフサービス化の余地が大きかった。ただし、プレイヤーデータのプライバシーと権限管理が厳格に求められるため、ACL対応と安全性の確保が必須条件として提示された。

## 2. 顧客課題

- 問い合わせ急増に対してサポートスタッフ数を増やすだけでは持続可能でない
- プレイヤーごとに参照可能な情報が異なるため、権限外の情報を回答に含めてはならない
- ゲームタイトルごとにコンテンツが大量にあり、回答の根拠となる文書を人間が毎回特定するのが困難
- 不正確な回答がプレイヤーエクスペリエンスを損ない、レビューやSNSでのネガティブ評価につながるリスクがある
- 本番運用後の品質維持手順が整備されておらず、エージェントの精度が劣化しても検知できない

## 3. 主要要件

| 要件 | 優先度 |
|---|---|
| ACLトリミングによるプレイヤーロール別アクセス制御 | High |
| 回答への根拠ドキュメント引用の必須化 | High |
| 定期的な評価パイプラインによる品質測定 | High |
| Content Safetyによる有害コンテンツ自動フィルタリング | High |
| 複雑な問い合わせの人間エスカレーション | High |
| フィードバックと利用ログの収集と分析 | Medium |

## 4. 提案／実装内容

Azure AI SearchのACL対応インデックスとFoundry Agentを組み合わせた本番グレードのプレイヤーサポートエージェントを構築することを提案した。

## 5. 主要リスクと対策

- **ハルシネーション**: Grounded Retrievalで根拠必須化、評価パイプラインで継続検証
- **データ過剰共有**: ACLトリミングとロール別フィルタリングの二重実装
- **古いナレッジ**: 定期更新スケジュールと鮮度アラートを設定

## 6. 結果

提案は採択され、プロジェクトP002として受注に至った。

## 7. 再利用可能な教訓

- ゲームのプレイヤーサポートではACLトリミングが技術要件であると同時に法的リスク管理でもある
- 評価パイプラインは本番開始時に基準を設定しないと後から合意が困難になる
- Content Safetyの設定はゲームコンテンツの特性（暴力表現の許容度など）に合わせた調整が必要

## 8. 再利用時の注意

- ACL設計はゲームごとのコンテンツ権限モデルを事前に整理してから実装すること
- 他業界では「プレイヤーロール」相当の権限分類を業種に合わせて再定義が必要
