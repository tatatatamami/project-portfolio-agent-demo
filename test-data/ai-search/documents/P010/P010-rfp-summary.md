# P010 RFP Summary - Creator Support Agent

## 1. 背景

メディア事業者Customer Eではコンテンツクリエイターからの問い合わせ（収益化・権利管理・コンテンツポリシー）が増加し、サポートチームの対応能力が逼迫していた。クリエイターごとに参照可能な情報が異なり（契約種別・チャンネル規模・権利設定）、AIエージェントによるセルフサービス化に大きな期待が寄せられた。ただしクリエイターのデータ権限と情報オーナーの整理が完了しておらず、本番運用の責任体制も未確立であった。

## 2. 顧客課題

- クリエイターからの問い合わせ件数が月次で急増しサポートキャパシティが不足している
- クリエイターごとの参照可能情報（収益データ・権利情報）の管理が手動で限界
- サポートエージェントの回答精度が58%と低くクリエイターの不満につながっている
- データの利用権限と情報オーナーが未整理で、誰がどのデータを参照できるかが不明確
- 本番稼働後の運用責任者と評価指標が決まっていない

## 3. 主要要件

| 要件 | 優先度 |
|---|---|
| クリエイター別ACLトリミング | High |
| 著作権・帰属の根拠引用必須化 | High |
| 評価パイプラインによる品質測定 | High |
| 知的財産リスクのContent Safety | High |
| 収益・権利問題の専門家エスカレーション | High |
| クリエイターフィードバック収集 | Medium |

## 4. 提案／実装内容

クリエイター別ACL対応ナレッジエージェントの構築を提案したが、データ権限整理と本番運用責任者の確定を提案実施の前提条件として明示した。

## 5. 主要リスクと対策

- **データ過剰共有（High/Open）**: クリエイター別データ分離の設計が必要。権限設計の完了が前提
- **受け入れ基準未定義（Critical/Open）**: 評価指標・精度基準・エスカレーション条件の合意が未完了

## 6. 結果

競合他社の提案が採択され、失注した。

## 7. 再利用可能な教訓

- クリエイター向けAIエージェントではデータの権限設計が最も困難であり、提案前に情報オーナーの確定を求めることが重要
- 本番運用責任の未確定は評価段階で重大なリスクとして評価されるため、運用体制を提案書に含めること

## 8. 再利用時の注意

- メディア業界のクリエイター向けサービスでは収益情報・権利情報・個人情報が複雑に絡み合うため、権限設計に特別な注意が必要
- 評価指標の未定義は、顧客が「本当に成功したかどうか分からない」状態で本番稼働させるリスクを生む
